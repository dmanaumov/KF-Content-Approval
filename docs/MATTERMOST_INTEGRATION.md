# Интеграция с Mattermost Boards — что нужно проверить перед продакшеном

Boards API у Mattermost официально не документирован (это подтверждается и
на форуме самого Mattermost: "Boards endpoints aren't in the main API docs
yet"). Всё, что ниже реализовано в `backend/src/mattermostClient.js`,
восстановлено по исходникам плагина `mattermost-plugin-boards`
(регистрация роутов в `server/api/*.go`), а не по официальной спецификации.
Это рабочая отправная точка, а не гарантированно точный контракт для вашей
конкретной версии сервера.

## 1. Правильный префикс API — проверить первым

В `.env` есть `MATTERMOST_BOARDS_API_PREFIX`. Варианты, которые встречаются
в природе:

- `/plugins/boards/api/v2` — Mattermost 9+, Boards встроен как плагин с id `boards` (значение по умолчанию в этом проекте).
- `/plugins/focalboard/api/v2` — более старые версии, плагин с id `focalboard`.
- `/api/v2` — отдельно стоящий Focalboard personal server (не через Mattermost).

**Как проверить быстро:** открыть Boards в браузере под тем же сервером,
открыть DevTools → Network, обновить страницу борда — увидите реальные
запросы к API и их точный префикс.

## 1а. Получение борда — через список бордов команды, не напрямую

Изначально `getBoard()` дёргал `GET /boards/{boardId}` напрямую — но на
реальном сервере агентства этот эндпоинт не отдавал ожидаемого (см. историю
отладки). Зато подтверждено вживую (реальным ответом с продакшена), что
работает:

```
GET {prefix}/teams/{teamId}/boards
```

— отдаёт массив бордов команды, каждый с полным `cardProperties`. Поэтому
`getBoard(boardId, teamId)` теперь получает этот список и ищет нужный борд в
нём. Из-за этого **`MATTERMOST_TEAM_ID` обязателен** — берётся из URL борда:
`.../boards/team/{teamId}/{boardId}/{viewId}/{cardId}`.

## 2. Аутентификация

Сейчас используется `Authorization: Bearer <Personal Access Token>` от
отдельного технического аккаунта/бота + заголовок `X-Requested-With:
XMLHttpRequest` (в коде роутов плагина есть `requireCSRFToken`, который по
исходникам ожидает этот заголовок; для сессионной cookie-авторизации это
обязательно, для PAT — по всей видимости нет, но заголовок отправляется
всегда на всякий случай).

Проверить: включить `DEBUG_MATTERMOST=true`, запустить `GET
/api/boards/{boardId}/tasks` и посмотреть в логах контейнера, приходит ли
осмысленный ответ, а не 401/403.

Если PAT не работает — альтернативы:
- Personal Access Token обычного пользователя-участника нужных бордов
  (если Bot Accounts выключены в System Console).
- Возможно потребуется завести отдельного пользователя и добавить его
  участником в каждый борд/команду.

## 3. Формат свойства-даты

Значения date-свойств у Focalboard в разных версиях наблюдались в разных
видах: JSON-строка `{"from":1692400000000}`, «голый» epoch в миллисекундах,
простая строка `YYYY-MM-DD`. `taskMapper.js` (`parsePropertyDate`) пробует
все три варианта по очереди и возвращает `null`, если не подошёл ни один —
в этом случае дата публикации в интерфейсе просто не покажется, ничего не
упадёт. Если у вас на сервере другой формат — здесь единственное место,
которое нужно доработать.

## 4. Payload для PATCH свойства карточки

`patchCardProperty()` отправляет:

```json
PATCH /boards/{boardId}/blocks/{blockId}
{ "updatedProperties": { "<propertyId>": "<optionId>" } }
```

Это соответствует структуре `model.BlockPatch` из исходников Focalboard
(`UpdatedProperties map[string]string`), но не проверено вживую против
вашего сервера. Если после «Согласовать» в интерфейсе статус не меняется в
самой Mattermost Boards — это первое место для проверки: временно включить
`DEBUG_MATTERMOST=true` и посмотреть, какой ответ/код возвращает сервер на
этот PATCH.

## 5. Payload для комментария (правки)

`addCardComment()` создаёт блок типа `comment` через:

```json
POST /boards/{boardId}/blocks
[{ "id": "...", "boardId": "...", "parentId": "<cardId>", "type": "comment", "title": "<текст>", ... }]
```

Тоже best-effort реконструкция по модели блоков Focalboard. Если комментарии
не появляются на карточке в Mattermost — второе место для проверки тем же
способом (DevTools Network на реальном добавлении комментария руками).

## 6. Файлы/медиа

Файлы, прикреплённые к карточке, отдаются через **основной** (стабильный,
официально документированный) файловый API Mattermost:
`GET /api/v4/files/{fileId}` с тем же Bearer-токеном. Он не публичный, поэтому
наш backend проксирует байты через `/api/files/{fileId}` — включая
пересылку заголовка `Range`, это важно для воспроизведения видео на iPhone
Safari (проверялось на моках, `206 Partial Content` пробрасывается корректно
— но финальная проверка на реальном видео с реального сервера обязательна).

## 7. Общий борд на всех клиентов (реальная схема агентства)

Борд «Задачи SMM-Team» — один на всех клиентов, разделение по клиентам идёт
через select-свойство `Проект`. Это значит:

- `MM_PROJECT_PROPERTY_NAME` обязателен к настройке (по умолчанию `Проект`).
- Ссылка клиента ОБЯЗАНА содержать `?project=...` — иначе `/api/boards/.../tasks`
  вернёт `400 project_filter_required`, а не список задач (специально, чтобы
  не показать чужие карточки).
- `project` можно передавать как id опции свойства «Проект» (надёжнее,
  стабильнее к переименованиям) или как точный текст label — сопоставление
  регистронезависимое, но лучше использовать id.
- `Статус` (свойство согласования) — существующее внутреннее свойство
  агентства, переиспользуется как есть, а не заводится отдельное. Из-за
  этого approve/feedback от клиента **перезаписывают** внутреннюю
  production-стадию карточки — это осознанный выбор агентства, не баг кода.
- Опция «правки» (`MM_STATUS_CHANGES_LABEL`) сейчас = существующая
  `Корректировка`, отдельную под клиентские правки не заводили — то есть
  внутренняя пометка «нужна корректировка» и «клиент попросил правки»
  неразличимы для этого приложения.

## Чек-лист перед продакшеном

- [ ] Подобран верный `MATTERMOST_BOARDS_API_PREFIX` для вашей версии сервера.
- [ ] `MATTERMOST_TEAM_ID` заполнен (из URL борда).
- [ ] PAT технического аккаунта действительно получает список бордов команды.
- [ ] На борде есть свойство «Проект» с опцией на каждого клиента —
      `MM_PROJECT_PROPERTY_NAME` совпадает буква в букву.
- [ ] Ссылки клиентов содержат правильный `?project=`, задачи одного клиента
      не показывают карточки другого (проверить руками с двумя разными
      значениями `project`).
- [ ] `MM_STATUS_*_LABEL` совпадают буква в букву с реальными опциями
      свойства `Статус`.
- [ ] «Согласовать» в интерфейсе реально меняет `Статус` карточки в Boards UI.
- [ ] «Есть правки» реально добавляет комментарий и меняет `Статус` на
      `Корректировка` в Boards UI.
- [ ] Видео с реального борда проигрывается на iPhone Safari (Range/206).
- [ ] Карточки с `АРХИВ` и с внутренними стадиями (`Не начато`, `В процессе`,
      `ТЗ РАЙТЕРУ` и т.п.) не показываются клиенту.
- [ ] Проверено поведение при недоступном Mattermost (учения: остановить
      Mattermost, убедиться что клиент видит понятную ошибку, а не белый экран).
