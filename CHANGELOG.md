# Changelog

Релиз-ноты KF Content Approval. Каждая запись — что изменилось и зачем; ведётся прямо в репозитории, чтобы не копировать текст туда-сюда отдельно.

## 2026-10-14 — Еженедельная статистика по Telegram-каналам

### Добавлено
- Новая вкладка CEO-панели «Статистика» (`/ceo/telegram-stats`): посты, просмотры, реакции, комментарии, подписчики (с дельтой за период) и вовлечённость по каждому каналу, куда бот «Кот Василий» добавлен администратором.
- Backend: таблицы `bot_channel_posts` (снимок по посту) и `bot_channel_subscriber_stats` (append-only журнал подписчиков), колонка `bot_chats.username`.
- API для n8n:
  - `GET /api/bot/channels` — список каналов, готовых к еженедельному скрейпу (бот админ + есть публичный username).
  - `POST /api/bot/channel-posts` — массовый апсерт постов после скрейпа `t.me/s/<username>`.
  - `POST /api/bot/channel-reactions` — реалтайм `message_reaction_count`.
  - `POST /api/bot/channel-subscribers` — еженедельный снимок числа подписчиков.
  - `GET /api/ceo/telegram/channel-stats?from=&to=` — чтение агрегированного отчёта для панели (CEO-сессия).
- Ссылка «Статистика» добавлена в навигацию вкладки «Бот» (`bot-chats.html`).

### Известные ограничения
- Только публичные каналы — для приватных нужен был бы MTProto-клиент (реальный юзер-аккаунт), решили не делать из-за риска для аккаунта.
- Исторических данных нет — отчёт показывает только то, что реально пришло через новые эндпоинты начиная с этой даты, бэкфилла не будет.
- n8n-воркфлоу (сам скрейпинг и отправка данных в API выше) ещё не написаны — полное ТЗ для разработчика: `claude/kf-telegram-channel-stats-n8n-spec.md` в проекте «Мои IT дела».
- Ссылка на вкладку «Статистика» пока добавлена не во все CEO-страницы — на `access.html`, `api-keys.html`, `bot-leads.html`, `ceo.html` навигация ещё без неё.

## 2026-10-14 — Перенос задач с Mattermost на Postgres: схема + кнопка в CEO-интерфейсе

### Добавлено
- Схема в Postgres под будущее хранилище задач/медиа/переписки: `app_tasks`, `app_task_media`, `app_task_feedback` (замена Mattermost Boards как хранилища карточек — причины и план: `claude/kf-mattermost-to-postgres-migration.md` в проекте «Мои IT дела»).
- Новая вкладка CEO-панели «Миграция» (`/ceo/migration`): предпросмотр переноса (ничего не пишет, только считает) и отдельная кнопка реального запуска с подтверждением. Запуск идёт в фоне (не ждём его в HTTP-ответе — на ~1000+ карточках это минуты), прогресс и результат — через поллинг статуса.
- API: `GET /api/ceo/mattermost-migration/preview`, `POST /api/ceo/mattermost-migration/run`, `GET /api/ceo/mattermost-migration/status` (все — только для CEO).
- Перенос переиспользует текущую логику разбора карточек (`taskMapper.js`) и полностью перезаливает Mattermost-медиафайлы на disk.kontentferma (консолидация медиа в одном месте); переписка по согласованию переносится целиком, включая внутренние служебные пометки, а не только клиентский срез.
- Перенос идемпотентен: каждый запуск полностью пересобирает три таблицы заново (TRUNCATE + заливка) — повторный клик не задваивает данные.

### Известные ограничения
- Это пока только подготовка данных — роуты `index.js`, читающие/пишущие задачи, ещё работают через Mattermost как раньше (следующая фаза — переподключить их на эти таблицы). Нажатие «Выполнить перенос» заполняет Postgres, но приложение продолжает показывать данные из Mattermost, пока эта фаза не сделана.
- Частичная неудача перезаливки отдельного медиафайла не останавливает весь перенос — такой файл просто попадает в список ошибок в отчёте для ручного разбора.
